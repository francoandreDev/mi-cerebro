21. **Responsive mobile.** Disparado por un reporte del usuario 2026-07-10: entrar desde el navegador de un celular Android no permite ninguna acción de escritura en el FS (diagnóstico aparte, ver §9/§18 — Chrome Android no implementa `showDirectoryPicker`, la vía mobile real es el empaquetado Capacitor de §18c) y, en la misma sesión, auditoría visual a 393×852px reveló que el shell nunca tuvo tratamiento responsive: `workspace-sidebar.container.css` (el rail de íconos, ver §4.6.14) no tenía ni un `@media`, así que en cualquier viewport angosto el rail se comía ~56px fijos del ancho y el contenido de cada feature desbordaba sin wrap. Como Capacitor renderiza el mismo WebView con el mismo CSS que el navegador (§18), este paso vale para ambos targets a la vez — no hace falta un tratamiento aparte por plataforma. **Sin convención de breakpoint centralizada** (§4.6.14): cada componente sigue hardcodeando su propio `@media (max-width: …)`; este paso introduce `480px` como el valor de facto para "viewport de celular" allí donde no existía ya un breakpoint más laxo pensado para ventana angosta de escritorio (600-1280px, ya cubiertos por pasos previos). **Alcance de esta entrada:** deja fundada la base (shell + 2 páginas) y releva el resto pendiente; no pretende cerrar todas las pantallas en una sola pasada.       - **Verificación**: `bun run typecheck` limpio en las 5 pantallas; verificación visual en navegador sólo parcial — el bridge de Chrome (mismo problema recurrente de esta sesión) se colgó de nuevo al intentar confirmar `/trash` a 393px. Balance de llaves `{}` revisado a mano en los 7 archivos CSS tocados como chequeo de sintaxis mínimo dado que no hubo confirmación visual.
      - **Primera pasada sobre las 7 pantallas que ya tenían algún `@media` (sesión 11, sin verificación visual — el bridge de Chrome siguió colgado toda la sesión).** A diferencia de las anteriores (cero `@media`), acá el objetivo fue encontrar huecos en breakpoints ya existentes, no partir de cero:
        - **Calendar.** Bug confirmado (columna "Sábado" desbordando, ya diagnosticado en sesión previa): `.weekdays`/`.grid` (`light-table.component.ts`) usaban `repeat(7, 1fr)` — el mínimo automático de un track de grid es `auto` (contenido), no `0` (mismo gotcha que §21a con el rail). Fix: `repeat(7, minmax(0, 1fr))` + `min-width: 0` en `.day`. `toolbar.component.ts`: `.search` pierde su `min-width: 220px` bajo `@media (max-width: 480px)`.
        - **History.** El más grande y complejo (3227 líneas, 3 modos de zoom con layout propio). Fix acotado a red de seguridad, no rediseño: los 3 modos con columnas fijas (`360px 1fr` / `minmax(240-300px) 1fr` / `1fr minmax(300-360px)`) colapsan a `1fr` bajo `@media (max-width: 480px)` — `zoom-detail-stack` no se toca porque ya es una sola columna. No replica el comportamiento fino de cada metáfora (rail de switcher en strata, aside en panorama) en mobile; **pendiente una pasada de diseño dedicada por modo**, documentado en `docs/deferred/index.md`.
        - **Music.** `.zones` (grid de 3→2 columnas) nunca bajaba de 2 columnas — a 393px, `minmax(260px,1fr)` sola ya ocupa la mayoría del viewport. `@media (max-width: 480px)` colapsa a `1fr` con `overflow-y: auto` (las zonas se apilan y scrollean). Sin verificar si el resto de sub-componentes (`album-library`, `now-playing`, `playlist-editor`, `queue-panel`, `resonant-surface` — ninguno tiene `@media` propio) rompen dentro de esa columna única.
        - **Settings.** `.row` (input de texto + botón) no wrappeaba y el input no tenía piso de ancho — suma `flex-wrap: wrap` + `min-width: 120px` en el input. `.seg` (segmented control de tema/lead-time) ya hereda el wrap de `.row` sin cambios propios.
        - **Sync.** Único hueco real: `.lever-row` (grid 2 columnas) nunca colapsaba pese a que el resto de la pantalla (`.layout`, `.console`) ya tiene breakpoints en 1100px/900px — suma `@media (max-width: 480px) { grid-template-columns: 1fr }`.
        - **Writings-shelf.** El modal de biblioteca (`.grid`, `minmax(320px, 1fr)`) tiene un piso de 320px que puede exceder el ancho disponible en un celular de 375px una vez descontado el padding del modal — colapsa a `1fr` bajo 480px.
        - **Reminders.** Ya es la mejor cubierta de las 7 (breakpoint a 960px que convierte el panel de detalle en bottom-sheet correctamente) — sin cambios, no se tocó.
